# Kinds of work

For each kind: what counts as evidence, the unit of change, and the floors a careful professional expects. In a project run the floors are lenses for the hunt. A project's own standards replace them. Treat work of another kind as the nearest kind here, and say so in the bar.

- **Code** (library, tool, service). Evidence: the project's tests and the new ones; lint and type checks where the project has them; the real entry point run on a representative input and on edge inputs (empty, malformed, unicode, large); an install-from-clean run. For a command-line tool also: `--help` matches the behaviour, exit codes differ for success, a usage error and a bad file, and errors go to stderr. Unit: one behaviour and its test. Floors: every documented behaviour has a test that fails when it breaks; no test depends on the clock, the network or the order it runs in; bad input at a trust boundary gives a clear error and no traceback; no secret in the repository; no unsafe handling of input, sign-in or files; the documents match the behaviour; it stays usable at ten times the sample size.
- **Interface** (site or app). See `interfaces.md`.
- **Document or research.** Evidence: each factual claim compared with the source it rests on, opened in this session; links and anchors resolve; every code sample runs or parses; every number recomputed; length and required sections; a `judge` condition on clarity for the named reader. When helpers read sources for you, a row counts only with a short quotation copied from the source, and you open again every source you build on. Where sources disagree, say so, and check that dates and versions are current. Unit: one section, or one kind of defect across the document. Floors: every statement supported by a source you opened, or removed, or marked as needing one; no invented citation, statistic or quotation; no contradiction; one term per thing. Never lengthen a document to improve it, and never cut something the brief or the documents require to satisfy a check or a judge.
- **Data or model.** Evidence: a metric from a fixed script, split and seeds, repeated for its spread; a leakage check; row counts before and after; spot-checked samples; the schema. A backup exists before any destructive step. Unit: one experiment, one variable changed. Floor: a held-out set never tuned on, looked at only at the end (phase 3 in a project run).
- **Video, audio, images.** Evidence comes from the delivered file, not the plan: container, duration, black or frozen or silent stretches, loudness, cut positions; for image sets, that the saved file is the generated one, and the whole set viewed as one sheet. Unit: one shot or asset. Humour, payoff, force at phone size, style and sound are `owner` conditions; a model may rank or flag to help him, and the report says that nobody listened. Paid generation needs the owner's go-ahead.
- **Game.** Evidence: an automated play-through of the main path that fails on errors, hangs and stuck states. Look and fun are `owner` conditions; a model may rank captures beside agreed references to help him.
- **Deploy or live system.** Evidence: the deployment status reads ready; a health URL returns the expected status and content; the logs are clean; no secret is in the repository or the logs; you can state the way back (for a first deploy, pausing or removing it; later, promoting the previous one). Floor: a long-running job is supervised and has a heartbeat whose absence somebody notices, and nothing it needs sits in storage that gets swept, such as `/tmp`. See `live.md`.
- **Skill or prompt.** Evidence: a fresh agent given a realistic task with the skill loaded, and a reading of what it actually did. A description of what it should do is not evidence.

## Running checks

- `cmd | tail` reports the exit code of `tail`, not of `cmd`. Use `cmd > out.log 2>&1; echo "exit=$?"`, or `${PIPESTATUS[0]}`.
- Wrap anything that can hang in `timeout <seconds>`. Run a long job in the background and come back when it finishes; do not poll in a loop.
- A test that passed before your change proves nothing about your change. See the new test fail without it.
- A change aimed at a number (speed, size, a score): measure three times before and three times after, and count the gain only if the medians differ by more than the spread, meaning the range of the three runs before.
- One evidence line per condition is enough: `C3 met: python3 wordstat.py empty.txt; echo exit=$? -> no output, exit=0`.
